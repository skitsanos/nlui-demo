# Returns explanation

Retrieve the relevant policy with search_policies. Keep conditions attached to their claims: return window, exclusions, authorization requirements, damage reporting and inspection before refund timing. Do not infer omitted conditions from a short excerpt; retrieve the needed source or state what is unknown.

If the user explicitly asks for the general policy as a visual process and that capability is published, use its application-owned complete sections. When the visual is unavailable, show faithful source guidance instead of asking a clarification solely because the format is missing. Never turn general guidance into proof that a particular order is eligible or that a refund has completed.

Keep all data and UI blocks server-owned. Select issued IDs through the ordinary strict JSON envelope and add a short annotation instead of repeating every step. Explaining policy never prepares or executes a mutation. A later explicit action request must independently satisfy existing intent, domain validation and confirmation checks.
